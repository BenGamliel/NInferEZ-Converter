# שימוש בממיר הנייד

1. חלצו את כל ה־ZIP לתיקייה שאפשר לכתוב בה.
2. הפעילו את `NInferEZ.Converter.exe`.
3. בחרו Guided wizard, בחרו קובץ מודל או תיקיית checkpoint ולחצו Check model.
4. השלימו את רשימת הקבצים הנדרשים: ניתן לבחור תיקייה מתאימה או קבצים בודדים.
5. לחצו Scan conversion options והשוו פרופילים, גודל משקולות וקידודים בפועל.
6. בחרו אפשרות במפורש, עברו ל־Review ובחרו פלט `.ninfer` חדש.
7. לחצו Convert model. AUTO מוצג כאפשרות עם תוכנית מפורטת, ואינו נבחר בשקט.

בקובץ GGUF נדרשים config ו־tokenizer תואמים לאותו מודל. ניתן לצרף קובצי
config/tokenizer/template/generation בנפרד, גם מתיקייה אחרת. במודל Safetensors
מפוצל בחרו את תיקיית המודל או את האינדקס; shard חסר ניתן לצרף ממיקום אחר,
בלי לשנות את האינדקס המקורי.

Manual setup חושף את כל ההגדרות: פרופיל, רכיבים נלווים, מקורות וקובצי משאבים,
מתכון מובנה או Python, הגדרות לכל משקולת, גודל מקטעים ופיצול קבצים, ראש
Proposal ודירוג טוקנים, בדיקת מנוע וייבוא/ייצוא בקשת JSON. יש לבצע Check &
preview לפני ההמרה. שינוי בתוכנית או בקבצים מאז הבדיקה מחייב בדיקה מחדש.

הסריקה מציגה אפשרות לירידת דיוק, אך אינה מודדת איכות תשובות. הגדלת מספר
הביטים של מודל שכבר דחוס לא מחזירה מידע שאבד. אומדן גודל המשקולות אינו
אומדן VRAM מלא. קלט .ninfer מאפשר אריזה מחדש/שדרוג, ולא קוונטיזציה מחדש.

ההתקדמות מציגה בתים שנכתבו בפועל. אחרי הכתיבה מתבצעת בדיקת הפלט.
Cancel מבטל את העבודה ומנקה את הפלט הזמני. קובץ קיים אינו נדרס.

התמיכה נקבעת לפי הארכיטקטורה, מבנה המשקולות והקידוד, ללא רשימת שמות מודלים.
ברירת המחדל ממירה את רכיב הטקסט. רכיבי Vision, MTP ו־DFlash נבחרים במפורש
בשני המצבים, יחד עם מקורות נוספים אם הם נדרשים.

בדיקת התאימות מאמתת את תוכנית ההמרה. כדי לבדוק גם הפעלת טקסט על GPU אפשר
לבחור `ninfer-serve.exe` מתאים תחת Engine verification; הבדיקה תרוץ לפני
שמירת הפלט הסופי. בדיקות Vision ורכיבי טיוטה דורשות גם בדיקה עם הקלט המתאים.

הממיר עובד ללא התקנה וללא אינטרנט, ומשתמש ב־CPU להמרה. יש לשמור את כל תיקיות
החבילה יחד. ה־Backend העצמאי נמצא ב־`NInferEZ.Converter.Backend.exe`; תיעוד
הפקודות וממשק JSON נמצא ב־BACKEND.md.
